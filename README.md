# 精工图谱 · 平湖工厂 · 工业制造官网首页

Vue 3 + Vite 实现的工业制造企业首页，主题为**设计成果图纸在线浏览**。
整体为报纸（印刷品）质感，但色调偏白偏淡：近白纸底 + 墨黑 + 淡绿交互色；
边框语言为**左下 + 右上两个角标边框 + 圆角**，线性图标，宋体排版。

## 快速开始

```bash
npm install          # 安装依赖
npm run dev          # 开发预览（默认 http://127.0.0.1:5273）
npm run build        # 生产构建 → dist/
npm run preview      # 预览构建产物
npm run smoke        # jsdom 冒烟测试（挂载 + 描线动画 + 滚动驱动 + 零件对比区）
npm run check:static # 静态产物自检
```

> Windows 沙箱环境提示：Vite 在受限沙箱下会因 `exec("net use")` 的子进程管道报 `EPERM`，
> 需在放宽权限的终端中运行 `npm run dev` / `npm run build`。

## 01 销售端 · 客需需求粗整理

`RequirementIntake.vue` —— 流程第一步，**只做粗整理，不填完整表单**：

- **左**：客户原话（微信语音转写体，可编辑）+「重新整理 / 恢复样例」+ 三步进度（客户口述 → 销售整理 → AE 初判）
- **右：三段对话**
  1. **客户 · 王工**：原话气泡（微信语音转写）
  2. **销售 · 陈工**：把原话拆成 **6 条要点**（客户/项目、应用、关键参数、数量交期、定制点、认证）
  3. **AE · 李工**：凭经验**初判产品族**（CAHB 系列电动推杆）、给出初步结论（倾向 CAHB-22-D2E）并列出 **3 项缺失信息**（静态载荷、温度上限、认证范围）
- **输出：AE 初判卡（粗）** —— 客户/iCRM、产品族、应用、关键参数（标「口述」）、数量交期、初步结论、缺失信息，底部两个动作：`导出初判`、`进入 01-00 逐节详填`
- **下：客户附件信息** —— 5 个附件（500413 / 500425 / 两份 CAHB 规格图 / 现场照片），含大小、来源、状态与"该附件提供的关键信息"；底部附件要点 3 条
- 关键参数从原话里正则抽取（`48V` / `3500N` / `30mm/s` / `行程 50` / `EAU 50`），改文本再点「重新整理」会跟着变

## 02 产品目录检索 · 图纸与 BOM（含两个分支页签）

`ProductCatalogChat.vue` —— chatbot 外壳，前置输入写死为
**「基于销售的信息检索产品目录，匹配可能的产品并展示图纸 / BOM 信息」**。
工具视图里有 **2 个分支页签**（由需求关键词自动路由，也可手点）：

> 客户需求能在产品目录里检索到 → 走 **① 产品目录匹配**；检索不到或需改制 → 走 **② 客制化目标匹配**。

**① 产品目录匹配**（两级目录 → 有图纸才展开）

- **大分类**（3 个）：法兰连接件 96% / 密封件 88% / 轴承支撑 72%，带匹配度与产品数
- **小分类 · 具体产品**（当前大分类下）：平焊法兰 DN160、对焊法兰 DN160、带颈法兰 DN160 /
  端面密封垫 ⌀160、骨架油封 FB 40×62×8 / 立式轴承座 H1-120；
  每个产品显示 匹配度 / 图号 / 规格 / 材质 / 库存与交期 / **有图纸·BOM 或 无图纸**
- **选中产品 → 图纸 / BOM（如果有）**：有图纸则 3 : 1 展开 `DwgViewer` + `BomPanel`

  无图纸则给出空态卡片「暂无现成图纸 / BOM」+「提交出图申请」「改用相近产品」

**② 客制化目标匹配**（`CustomMatchTool.vue`，即原第 03 区内容并入此处）

- 顶部说明条：`客制化` 徽标 + 目标（法兰盘 DN160 · 8×⌀13 均布 · 配 ⌀40 轴）+ 为什么走客制化

  （`outBack` 回弹 + 高亮），未装入的基准位显示淡绿虚线空位，全部就位盖「装配完成」印章；
  **滚轮缩放**（0.6×~3×，光标锚点）、**空白处拖动平移**、工具条「放大 / 缩小 / 适合窗口 / 自动组装 / 全部散开 / 复位」；
  零件上不显示名称与尺寸，底部装配清单显示「待装入 / 已装入」
- **右（1）页签面板**：类别（**20 类**零件 + 筛选输入行，列表可视 5 行其余滚动）/ 规格（5 个历史规格 + 版本时间线）/
  对比（同心圆 + 外径·孔数·重量·版本·日期差异）/ 上载至M3（按组装台实时生成 BOM → 上载，单据 `-014`）
- 分支路由：输入里明确提到「客制化 / 定制 / 没有匹配 / 改制 / 拼装 / 组装」→ 切到 ②；
  提到「目录 / 标准产品 / 现货 / 库存」→ 切回 ①；否则**保持当前分支**

## 部署（纯静态，无需后端）

产物只有 3 个文件，`base: './'` 使用相对路径，放根目录或任意子目录都能跑：

```
dist/
├─ index.html            1.2 KB
└─ assets/
   ├─ index-*.js       183 KB（gzip 66 KB）
   └─ index-*.css       41 KB（gzip 8.5 KB）
```

```bash
npm run build        # 产出 dist/
# 把 dist/ 整个目录上传到静态服务器即可
npm run check:static # 本地零依赖起服务自检（确认可独立访问、无外部请求）
```

Nginx 示例（放在子目录 `/drawings/` 时）：

```nginx
location /drawings/ {
    alias   /var/www/nyonic/dist/;
    index   index.html;
    try_files $uri $uri/ /drawings/index.html;
}
```

要点：

- **无路由**：单页无 vue-router，不需要 history fallback 重写规则（上面的 `try_files` 只是兜底）。
- **零外部请求**：字体用系统字体栈，图标是内联 SVG，图纸是内联 SVG，**不请求任何 CDN / 字体 / 图片**，
  内网、离线环境可直接部署。
- **无接口调用**：BOM 提取、M3 上载、需求分析对话等均未接后端，页面可独立运行。
- 若部署在根目录并希望用绝对路径，把 `vite.config.js` 的 `base` 改成 `'/'` 后重新构建。
- 不要用 `file://` 直接打开 `dist/index.html`（ES Module 受同源策略限制），请走 http 服务。

### 想接真实 DWG 在线浏览

两种路线：

1. **保持纯静态**：用 ODA File Converter / 自研脚本把 DWG 批量转成 SVG（或 DXF→SVG），
   替换 `src/components/drawings/` 下的组件内容，仍然是零依赖静态站点（推荐内网场景）。
2. **接在线服务**：给 `<DwgViewer>` 传 `embed-url` 指向 Autodesk Platform Services、
   ODA 或公司内网的转换/预览服务，窗口会自动切换为 iframe 嵌入（此时需要该服务的可用性）。

## 设计语言（可调）

- 配色令牌在 `src/styles/base.css`：`--paper` 系列为近白纸底，`--ink` 为墨色，`--accent` 为淡绿交互色。
- 角标边框：全局类 `.corner-box`（及 `.paper-card`）只用**右上 + 左下**两段边框，长度由 `--corner` 控制，圆角由 `--r-md` 控制；
  组件里用 `<div class="side__block corner-box">` 这种叠加写法即可复用。
- 圆角令牌：`--r-xs 5px / --r-sm 9px / --r-md 14px / --r-lg 20px / --r-pill`。
- 纸纹与明暗在 `body::before`（噪点，`opacity: .22`）与 `body::after`（极淡渐变），想更"白"就继续调低这两处。
