# 网页表单 → 浏览器插件：信息传递方案调研

> 场景：内部流程演示站点（本仓库）里生成 / 提取出的 BOM 与需求数据，需要送进 M3 的浏览器插件，
> 由插件在 M3 系统里创建 / 更新物料主数据，并把 M3 的回执再送回来（页面上的「监视 M3 传入数据」）。

---

## 一、可选通道总览

| 方案 | 方向 | 需要什么权限 / 配置 | 优点 | 局限 |
| --- | --- | --- | --- | --- |
| **A. `window.postMessage` / CustomEvent**（页面 → content script） | 页面 ↔ 注入脚本 | 插件 `content_scripts.matches` 覆盖页面域名 | 最简单、无特殊 API、双向可做（脚本再 postMessage 回来） | 同源页面任何脚本都能发；**不是安全边界**，必须校验数据 |
| **B. `chrome.runtime.sendMessage(extensionId, …)`**（页面 → 扩展） | 页面 ↔ Service Worker | manifest `externally_connectable.matches` 白名单页面源 | 页面无需被注入、直接进 SW；可 `connect` 长连接双向 | 页面要写死扩展 ID；SW 里要校验 `sender.origin`；只有顶层框架可发 |
| **C. content script → SW → `chrome.tabs.sendMessage`** | 扩展内部 | `storage`、`tabs`/`scripting`、目标站 `host_permissions` | 推荐主链路：页面只跟脚本说话，写入 M3 由脚本完成 | SW 会休眠，状态要落 `chrome.storage` |
| **D. 剪贴板（复制 JSON → 插件弹窗粘贴）** | 用户中介 | 无（`clipboard` 权限可选） | 零集成、最稳、易审计 | 需人工一步，不能自动 |
| **E. 本地 WebSocket / HTTP 桥**（`ws://127.0.0.1`） | 页面/插件 ↔ 本机服务 | 本机安装桥服务；`host_permissions` 允许 localhost | 可与桌面客户端（M3 客户端）、打印、文件系统打通 | 要部署与升级本机服务；跨端运维成本 |
| **F. Native Messaging** | 扩展 ↔ 本机程序 | manifest `nativeMessaging` + 本机 host 注册 | 能调用本地程序、读写本地文件 | 安装注册表 / JSON 描述文件，企业分发需统一打包 |
| **G. 生成文件 + `downloads` 监听** | 页面 → 磁盘 → 插件 | `downloads` 权限 | 可留档 | 触发下载很吵、时序不可靠 |

**结论：**

- 页面与插件同域（或插件会注入本页）→ 用 **A 作为页面侧接口 + C 作为扩展内部链路**，最省事也最好调试。
- 页面不给注入（跨域、第三方托管）→ 用 **B（externally_connectable）**。
- M3 是桌面客户端 / 需要写本地文件 → 才考虑 **E / F**。

---

## 二、推荐主链路（本 demo 采用）

```
[页面] 上载至 M3 / 提取 BOM
   │ ① window.postMessage({ source:'xinyi-web', type:'M3_BOM_IMPORT', payload })
   │    （同时派发 CustomEvent('m3:bom-import') 供脚本二选一监听）
   ▼
[content script]（注入页面，isolated world）
   │ ② 校验 event.origin / event.source、字段白名单、体积上限
   │ ③ chrome.runtime.sendMessage({ type:'M3_IMPORT', payload, idempotencyKey })
   ▼
[service worker]（MV3，会休眠）
   │ ④ 写入 chrome.storage.session 队列（防 SW 休眠丢任务）
   │ ⑤ 找已打开的 M3 标签 → chrome.tabs.sendMessage(tabId, { type:'M3_FILL', payload })
   │    没有 → chrome.tabs.create({ url: M3_URL }) → 等 tabs.onUpdated('complete') 再发
   ▼
[M3 页面的 content script]
   │ ⑥ 按字段填表：原生 setter + dispatch input/change（兼容 React/Vue 受控组件）
   │ ⑦ 提交后抓取回执（单据号 / 物料号 / 错误码）
   ▼
回程：⑦ → SW（storage + 广播）→ 页面 content script window.postMessage({ type:'M3_ACK' }) → 页面「监视窗口」追加一条
```

### content script（注入页面）

```js
// manifest: "content_scripts": [{ "matches": ["https://demo.example.com/*"], "js": ["page-bridge.js"], "run_at": "document_idle" }]
const ALLOWED = new Set(['https://demo.example.com'])

function valid(d) {
  return (
    d && d.source === 'xinyi-web' && d.type === 'M3_BOM_IMPORT' &&
    Array.isArray(d.rows) && d.rows.length <= 500 &&
    d.rows.every((r) => typeof r.code === 'string' && r.code.length < 64) &&
    JSON.stringify(d).length < 256 * 1024
  )
}

window.addEventListener('message', async (e) => {
  if (!ALLOWED.has(e.origin) || e.source !== window) return   // 防伪造
  if (!valid(e.data)) return
  try {
    const res = await chrome.runtime.sendMessage({
      type: 'M3_IMPORT',
      payload: e.data,
      idempotencyKey: e.data.idempotencyKey,
    })
    // 回执再送回页面
    window.postMessage({ source: 'm3-connector', type: 'M3_ACK', ok: res?.ok, docNo: res?.docNo }, e.origin)
  } catch (err) {
    window.postMessage({ source: 'm3-connector', type: 'M3_ACK', ok: false, error: String(err) }, e.origin)
  }
})
```

### service worker

```js
const M3_URL = 'https://m3.example.com/plm/material'

async function ensureM3Tab() {
  const [tab] = await chrome.tabs.query({ url: M3_URL + '*' })
  if (tab) return tab.id
  const created = await chrome.tabs.create({ url: M3_URL })
  await new Promise((resolve) => {
    const onUpd = (id, info) => {
      if (id === created.id && info.status === 'complete') {
        chrome.tabs.onUpdated.removeListener(onUpd)
        resolve()
      }
    }
    chrome.tabs.onUpdated.addListener(onUpd)
  })
  return created.id
}

chrome.runtime.onMessage.addListener((msg, sender, sendResponse) => {
  if (msg?.type !== 'M3_IMPORT') return
  // 只接受来自白名单页面的消息
  const from = sender.origin || sender.url || ''
  if (!/^https:\/\/demo\.example\.com/.test(from)) return sendResponse({ ok: false, error: 'origin' })

  ;(async () => {
    await chrome.storage.session.set({ queued: msg })       // 防休眠丢任务
    const tabId = await ensureM3Tab()
    const res = await chrome.tabs.sendMessage(tabId, { type: 'M3_FILL', payload: msg.payload })
    await chrome.storage.session.remove('queued')
    sendResponse(res ?? { ok: true })
  })()
  return true // 异步响应
})
```

## 三、manifest 关键片段

```json
{
  "manifest_version": 3,
  "name": "M3 Connector",
  "version": "1.4.2",
  "permissions": ["storage", "tabs", "scripting"],
  "host_permissions": ["https://demo.example.com/*", "https://m3.example.com/*"],
  "content_scripts": [
    { "matches": ["https://demo.example.com/*"], "js": ["page-bridge.js"], "run_at": "document_idle" },
    { "matches": ["https://m3.example.com/*"], "js": ["m3-fill.js"], "run_at": "document_idle" }
  ],
  "externally_connectable": { "matches": ["https://demo.example.com/*"] },
  "background": { "service_worker": "sw.js", "type": "module" }
}
```

> 只有用到方案 B（页面直接 `chrome.runtime.sendMessage(extensionId, …)`）时才需要 `externally_connectable`；
> 走方案 A 的话它可以省掉，页面完全不需要知道扩展 ID。

## 四、安全与合规要点（别省）

1. **绝不信任页面数据**：校验 `origin`、`event.source === window`、字段白名单、长度 / 条数上限、只接受 JSON 可序列化值。
2. **不把页面 HTML 注入 M3**：只搬结构化字段，避免 XSS 通过插件"提权"进内部系统。
3. **防重放 / 重复导入**：带 `idempotencyKey`（本 demo 用 BOM 单据号），SW 侧用 `chrome.storage` 去重。
4. **排队与重试**：SW 会休眠，任务先落 `chrome.storage.session`；M3 不可用时指数退避重试（≤3 次）。
5. **最小权限**：只在需要时申请 `scripting`/`tabs`；能 `activeTab` 就不要全站 `tabs`。
6. **审计留痕**：插件侧记录「谁在什么时候导入了哪张单据」，与企业 SSO 的工号绑定。
7. **HTTPS 与内网证书**：`externally_connectable` 只对 HTTPS 源生效；内网自签证书要在企业策略里信任。
8. **扩展分发**：MV3 私发（`ExtensionSettings` 策略 / 企业强制安装），避免用户手动拖装。

## 五、调试清单

- 页面 `console` 与 content script `console` 是**两个执行环境**（isolated world），断点要分别打。
- SW 会休眠：`chrome://extensions` → 点 "Service Worker" 打开检查器，勾选 "Persist" 便于调试。
- 消息未送达先看 `chrome.runtime.lastError`（多数是接收端不存在 / 权限不足）。
- 页面侧 `postMessage` 第二参数必须是**明确 origin**（不要 `'*'`），否则回执会被别处读到。
- 受控表单填不进去，99% 是没走原生 setter + 事件派发。

---

## 六、与其它方案的取舍补充

- **M3 是桌面客户端**：E（本机 WebSocket 桥）比 F（Native Messaging）更好维护——桥服务可独立升级，插件只需要连 localhost。
- **只想"能拷进去"**：D（剪贴板）成本最低，适合先上线再补自动化。
- **需要跨浏览器（Edge/Chrome 双端）**：MV3 代码通用，`externally_connectable` 两端行为一致；Firefox 需改用 `browser.runtime` + `browser_specific_settings`。

## 七、本 demo 现状

- 页面侧：`BomPanel.vue` 在「上载至 M3」成功后同时派发 `window.postMessage` 与 `CustomEvent('m3:bom-import')`，
  payload 结构即上文 `detail`（含 `idempotencyKey`、`target`、`rows`）。**未注入插件时不会有任何副作用。**
- 插件侧：本仓库不含扩展代码，按上文第二节实现即可对接；`M3_ACK` 回执可直接喂给页面的「监视 M3 传入数据」列表。
